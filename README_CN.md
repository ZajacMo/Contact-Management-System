# 通讯录管理系统

*[English](README.md)*

> **仓库状态：已归档。**
> 这是一个 2022 年完成的课程作业项目，仅作参考保留，不再维护。

一个基于 **MFC**（Microsoft Foundation Classes）编写的 Windows 桌面通讯录
管理系统，提供密码登录、联系人列表、增删改查以及基于文件的持久化存储。

## 功能特性

- **密码登录** —— 密码以混淆形式保存，而非明文。若尚未设置密码，首次输入的
  密码会被保存下来，而不是被当作错误密码拒绝。
- **联系人列表** —— 显示每位联系人的序号、姓名和电话，按年龄从大到小排列。
- **新建联系人** —— 姓名和电话为必填项，年龄可填但必须是非负整数，重复的联系人会被拒绝。
- **查看、修改、删除** —— 详情对话框显示全部字段，并可修改或删除记录。
- **修改密码** —— 需要提供原密码。
- **清空联系人** —— 确认后清空整个列表。
- **数据持久化** —— 联系人写入 `contact.txt`，下次启动时自动载入。

## 界面与操作流程

程序启动后进入登录界面：

```
┌─────────────────────────────────────────────┐
│        通讯录管理系统 1.11                    │
│                                             │
│   欢迎使用通讯录管理系统 1.11                  │
│                                             │
│        请输入密码：                          │
│        [_____________________]              │
│                                             │
│   [x] 我已阅读安全协议                        │
│                        [ 登陆 ] [ 退出 ]     │

```

勾选协议框，输入密码后点击**登陆**（或按回车）。若当前目录不存在
`secret.txt`，首次输入的密码会被保存为新密码。

主界面列出联系人，并提供**新建**、**详细**、**清空**、**密码**和**保存**
五个按钮：

```

│  当前联系人数量：3                                    │
│  ┌──────┬─────────────┬──────────────┐               │
│  │ 序号 │ 姓名        │ 电话         │               │
│  ├──────┼─────────────┼──────────────┤               │
│  │ 1    │ Bob         │ 119          │               │
│  │ 2    │ Alice       │ 110          │               │
│  │ 3    │ Carol       │ 120          │               │
│  └──────┴─────────────┴──────────────┘               │
│                              [ 新建 ] [ 详细 ]       │
│                              [ 清空 ] [ 密码 ]       │
│                              [ 保存 ]                │
└──────────────────────────────────────────────────────┘
```

选中某一行后点击**详细**打开详情对话框，其中有**修改**和**删除**按钮。
点击**保存**将列表写入 `contact.txt` 并退出。

## 编译

### 环境要求

| 项目 | 版本 |
|---|---|
| 操作系统 | Windows 10 及以上 |
| Visual Studio | 2019 或更高（推荐 2022） |
| 工具集 | v143（`MFCApplication1.vcxproj` 中的 `PlatformToolset`） |
| MFC | **必需** —— 需安装"适用于最新 v143 生成工具的 C++ MFC"组件 |
| Windows SDK | 10.0 或更高 |

MFC 并非 Visual Studio 的默认安装组件。若未安装 MFC，编译会报错：

```
error MSB8041: 此项目需要 MFC 库。
```

### 使用 Visual Studio 编译

1. 打开 `通讯录1.11.sln`（也可直接打开 `MFCApplication1.vcxproj`）。
2. 选择配置：`Debug` 或 `Release`，`x86` 或 `x64`。
3. 执行**生成 → 生成解决方案**。
4. 可执行文件生成在 `Debug\` 或 `Release\` 目录下。

解决方案文件名含有中文字符。若你的检出路径给工具链带来问题，可以直接打开
`MFCApplication1.vcxproj`，它不依赖解决方案文件。

### 源文件编码

所有 `.cpp` 和 `.h` 文件均为 **UTF-8 带 BOM**，MSVC 可自动识别；资源脚本
`MFCApplication1.rc` 为 **UTF-16 LE 带 BOM**，即资源编辑器写出的格式。

## 运行

程序在**当前工作目录**下读写两个文件：

| 文件 | 用途 |
|---|---|
| `contact.txt` | 联系人列表，首次保存时创建。 |
| `secret.txt` | 混淆后的登录密码，首次登录时创建。 |

请在希望存放这些文件的目录中运行可执行程序。从构建输出目录运行没有问题，
只需注意 `contact.txt` **不在**版本控制范围内。

若忘记密码，删除 `secret.txt` 后重新登录即可——下一次输入的密码会成为新
密码。程序没有密码找回机制，存储的密码也无法还原为明文。

## 项目结构

```
├── contact.h          # contact 与 ContactList：数据模型与持久化
├── lock.h             # 密码混淆与编辑框读取辅助函数
├── MFCApplication1.*  # 应用程序对象、启动流程与共享的列表实例
├── MFCApplication1Dlg.* # 登录对话框
├── MENU.*             # 主界面：联系人列表与操作按钮
├── DIALOG_ADD.*       # "新建联系人"对话框
├── DIALOG_DETAIL.*    # "联系人详细"对话框
├── DIALOG_CODE.*      # "密码管理"对话框
├── SIGNSUCCESS.*      # 自动关闭的提示对话框
├── MFCApplication1.rc # 对话框布局与界面字符串
├── resource.h         # 资源标识符
└── res/               # 图标与不可编辑的资源片段
```

### 核心类型

**`contact`** —— 一条记录。字段为私有，通过 `f_*()` 访问器读取。
`ContactList` 是友元，以便在从磁盘读取时直接填充记录。

**`ContactList`** —— 联系人集合。它使用一个长度为 1000 的固定数组，空槽位
以 `age == -1` 标记，这也是新建联系人时校验年龄必须为非负整数的原因。

`ContactList::line()` 按年龄从大到小排序并返回已占用槽位数量。由于空槽位的
年龄为 `-1`，它们总会排到最后，因此已占用的联系人始终位于下标
`[0, count)`。该顺序既是列表视图的显示顺序，也是 `SaveContact()` 写入磁盘
的顺序，属于可观察行为而非实现细节。

## 数据格式

`contact.txt` 是制表符分隔的文本文件，每行一条记录：

```
姓名 <TAB> 电话 <TAB> 性别 <TAB> 年龄 <TAB> 住址
```

列表以一条首字段为 `off` 的哨兵记录结尾：

```
Bob	119	M	40	Addr B
Carol	120	F	20	Addr C
off	1	1	-1	1
```

说明：

- **只有制表符是分隔符。** 字段内可以包含空格，`Alice Smith` 能被正确读回。
- **`-1` 表示"未填写"**，用于可选的 `sex` 和 `address` 字段；读回时转为
  空字符串。
- **`off` 哨兵记录表示列表结束**，其后的内容一律忽略。
- 文件的写入顺序与列表视图一致，即按年龄从大到小。

## 密码存储

密码不以明文保存。`lock.h` 在一个 62 字符的字母表上定义了一组单表代换：

```cpp
const char ArrSecret[]  = "qwertyuiHIJKLMNop[ABCDEFG]asdUVWXYZfghjkOPQRSTl;zxcvbnm,.?{}:|";
const char ArrObvious[] = "ABCDEFGHIJKLMNOPQRSTUVWXYZ1234567890abcdefghijklmnopqrstuvwxyz";
```

`ArrSecret[i]` 与 `ArrObvious[i]` 是同一个置换的两种表示。`setcode()` 将明文
的每个字符经 `ArrObvious` 映射为 `ArrSecret` 并写入 `secret.txt`；
`checkcode()` 则将存储的字符映射回来，与输入的密码比对。

例如，密码 `123456` 会存储为 `asdUVW`。

**这只是混淆，不是加密。** 替换表被编译进可执行文件且在源码中可直接阅读，
任何能读取二进制文件的人都能还原密码。它的意义仅在于让 `secret.txt` 中不
出现明文。请勿依赖它保护任何敏感数据。

密码仅允许使用上述字母表中的 62 个字符。若输入了表外字符，程序会在设置
密码时直接拒绝，而不是静默丢弃——被丢弃的字符会导致存储的密码与用户输入
的不再一致。

## 已知限制

以下问题源自最初的设计，归档时**未做修改**，此处列出以免造成意外：

- **密码保护并非真正的安全机制。** 参见[密码存储](#密码存储)。
- **非 ASCII 姓名依赖系统代码页。** 对话框文本经由 `CStringA` 转换，因此
  中文、日文等非 ANSI 字符集的姓名能否正确保存取决于机器的区域设置。
- **列表上限为 1000 条**，该上限是编译期常量。
- **联系人始终按年龄从大到小排列**，无法按姓名或电话排序。
- **没有撤销功能。** 点击**清空**会立即清空列表，唯一的补救是上一次保存的
  `contact.txt`。
- **只有点击保存才会写入磁盘。** 未保存直接关闭窗口会丢失改动。
- **`age` 同时用作空槽位标记。** 年龄为 `0` 的联系人是合法的，但详情对话框
  不会显示年龄 `0`，因为原代码用 `0` 表示"未填写"。

## 归档说明

本仓库于 2026-11-10 归档。归档前做了以下改动，使项目至少能够编译并阅读：

**已修复**

- 全部源文件统一为 UTF-8 带 BOM，所有注释与界面字符串翻译为英文。此前仓库
  中 GBK、UTF-8、UTF-16 混用，README 在 GitHub 上显示为乱码。
- **多重定义的链接错误。** `ContactList List`、`setcode`、`checkcode`、
  `informationget`、`Tip_m`、`Tip_s` 定义在头文件中，导致每个编译单元各有一
  份副本；链接之所以能通过，只是因为设置了 `/FORCE`。现在这些符号改为
  `inline` 或只保留唯一一份定义。
- **内存泄漏。** 登录与密码对话框中三处 `new char[]` 从未释放。
- **读取文件无边界检查。** `ReadContact()` 在递增下标时没有上限限制，损坏的
  `contact.txt` 会导致越界写入。
- **未检查文件句柄。** `fopen` 的返回值从未检查，缺少 `secret.txt` 时程序
  崩溃，而不是提示"尚未设置密码"。
- **用 `freopen` 充当文件 I/O。** 通过重定向 `stdin`/`stdout` 读写联系人
  文件的做法已改为 `std::fstream`。
- **硬退出。** `exit(0)` 会跳过析构函数并丢弃未保存的数据。
- **从克隆下来的仓库无法编译。** `.gitignore` 排除了 `*.sln`、`*.vcxproj`
  和 `*.rc`——恰恰是编译 MFC 项目所必需的文件。这些文件现已纳入版本控制。
- **解决方案中的失效引用。** 解决方案引用了目录已不存在的 `通讯录1.10`
  项目，导致解决方案无法加载，现已移除。
- **文件名大小写不一致。** 工程引用的是 `Resource.h`，磁盘上的文件却是
  `resource.h`。
- **1.4 MB 的 Visual Studio 临时文件**（资源编辑器的 `RCa*` / `RD*` 残留）
  已从版本控制中移除。

**已验证**

重写后的数据模型与密码代码使用 MSVC 19.44 编译，并通过测试程序验证：密码
往返、联系人插入、按年龄降序排列、按姓名与电话查找、删除、保存/载入往返、
`-1`"未填写"约定，以及文件缺失的情况，均与本文档所述一致。已存在的
`secret.txt` 仍能用创建它时所用的密码解锁。

**有意未做**

- MFC 框架本身、长度 1000 的固定数组，以及按年龄降序的排列规则。
- 替换密码算法。改用真正的密钥派生函数会改变磁盘格式，导致老用户无法
  继续使用。
- 界面布局与资源脚本中的对话框定义。

**未验证**

GUI **未**经过编译或运行：用于归档的环境中未安装 MFC，Visual Studio 在进入
编译器之前就以 `MSB8041` 失败。数据模型与密码代码是通过桩（stub）MFC 类型
直接编译验证的，但对话框的交互接线本身未经验证。
